# Project rules

- Regulation lookups (eCFR, Federal Register, Regulations.gov) run server-side in `/api/ed-source-desk/*` via `src/lib/ed-source-desk.server.ts`; keys never reach the client — keeps DATA_GOV_API_KEY secret and refusal rules un-bypassable.
- Golden eval cases live in `src/data/ed-source-desk/goldens.ts`; the pass badge only shows real published results — never compute percentages client-side.
- Phase 2 library tables `documents`/`chunks` are server-only (RLS on, no anon/authenticated grants, service_role only) — visitors never read or write content directly.
- Chunk embeddings use `google/gemini-embedding-2` at 3072 dims (`chunks.embedding vector(3072)`); changing model means re-embedding everything. HNSW needs a `halfvec(3072)` cast index (vector index limit is 2000 dims).
- Pilot retrieval uses exact vector search (no approximate index) on `chunks.embedding`; each chunk's `citation_ref` = human label + official URL text-fragment locator — keeps citations traceable to the source page.
- Every free-text citation must pass a topical-fit check (question's distinctive terms present in cited text; numbers/generic words excluded; keyword-guessed sections need 0.8, user-named numbers 0.6) — stops section numbers or broad keywords validating unrelated questions.
- Ask Regs searches imported handbook chunks read-only via `match_chunks` (service_role only, exact search, similarity ≥ 0.74 + fit check), shows only CURRENT_AWARD_YEAR (2026-27) passages verbatim — prior years stay stored but excluded; chunks split at plain-line section headings, never margin "###" notes.
- Federal Register search hits are answers only when the question asks for FR documents (FR/notice/proposed/recent); proposed rules never answer unless asked — notices and NPRMs do not answer "what determines" questions.
- eCFR calls are bounded (max 2 concurrent, 350ms gap, titles/section responses cached and shared in-flight) and 429/5xx retry up to 5 times within 20s; exhaustion returns mode `source-unavailable`, never a no-cite or other source — eCFR rate-limits bursts.
- Current-year handbook ranking is heading-aware (heading hits weigh double, multi-chunk sections judged whole, heading-verified sections may qualify from similarity 0.70); results carry `coverage` (partial/full) and `conditional` — global fit thresholds unchanged. A chapter's topic words (in more than half its section headings, e.g. "Pell" in Vol 7 Ch 2 — per chapter only; spreading them volume-wide erased real heading hits, U21) and a volume's topic words (in more than half its imported chapter titles, 3+ chapters, e.g. "Pell", "Grant" in Vol 7) never count as heading hits or heading precision — otherwise headings tie on them or a chapter where the word is rarer wins. Numbered variants the question names are checked in single, list or range form ("Formulas 1 through 4"): BBAY 1/2/3 must each appear for full fit; Formula N only decides completeness (listed as missing, not scored), because the section explaining how formulas are chosen never names them (U21). A question naming an aid program (Pell, Direct Loan, TEACH, FSEOG, Work-Study) gets no passages from a volume about a different program; the related-only shortlist ranks meaning among on-topic passages (fit >= 0.5). Among passages allowed to be the answer, the one missing fewer question terms comes first (ties keep rank), and an answer is "complete" only if the answer passage itself covers every question term.
- Word check runs on the full section text (never the capped display copy), drops filler words, treats "full time"/"full-time" as one, and matches capitalised abbreviations (ISIR, SAI, COA, BBAY, SAY, LEU, R2T4) only in capitals; short words match whole (cents ≠ centralized) — prevents false fits.
- Handbook retrieval pairs meaning search with plain word search; a rule section found only by word search does not upgrade a result to an answer, and examples count as the answer only when the question asks for an example.
- Missing definitions are looked up in the question's program definitions section first (690.2 Pell, 685.102 Direct Loans), then 668.2, then 600.2 — program terms like "Scheduled Federal Pell Grant" live only in the program section.
- Handbook passages found with help from word search (alone or both searches) are related only, never the answer — except a rule section (never an example) that qualifies on meaning alone (similarity ≥ 0.74), covers every question term, and whose heading names a non-topic question term: word search only confirmed it, and such an answer is always labelled partial, never complete. An example is the answer only if the question asks for one, the example contains the named item (e.g. BBAY 3), and word search didn't help find it — keeps word matches from upgrading results.
- Handbook chapters import only through the token-protected `POST /api/ed-source-desk/admin/import` (dry-run, import, promote) and land as `staged`; v1 `match_current_chunks` never returns staged rows, v2 shows them only in preview builds (Vite mode `development`) or on known preview hosts, never in the production build, and only a named `promote` makes them `in_force` — imports refuse to write unless the registry's expected checks pass.
- Handbook examples use fictional Pell maximum/minimum amounts: `fictional_amounts` passages are never the answer to an amount question, and the warning is shown outside the quote, never prefixed into `text`.
- A chapter without a reviewed manifest (e.g. Vol 7 Ch 3) is found from another chapter's link, passes only structural checks, and imports only with `confirm_content_hash` equal to its dry-run's `content_hash`; the owner reviews it on the preview before promote.
- The AI explanation (`POST /api/ed-source-desk/explain`) is owner-only (same bearer token as the admin import, 404 without it) and never public: it explains only the sources the normal lookup cited, every bullet must cite a source id, and a reply citing an unknown source, leaving a line uncited, or stating a dollar amount found only in fictional examples is discarded (one retry) — never shown.
- After each phase, update `docs/ed-source-desk/AI-EVIDENCE-LOG.md` with the decisions made (who proposed, who chose), measured results and new gaps — keeps the owner's resume claims traceable to artifacts; never overstate who wrote the code.
