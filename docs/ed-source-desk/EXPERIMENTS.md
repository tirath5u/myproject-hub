## How to use this registry

An experiment needs a stable case set and source version, a baseline, a named change, a full rerun, and a result that separates improvement from regression. A PR with several rule changes is a release fix, not a clean single-variable experiment. Do not infer success from a green unit test or an expected effect written in a PR. For future work, add a row before editing, change one factor where practical, then attach per-assertion preview and live receipts. Tirath approves golden labels and promotion.

## Required row for the next change

Before changing retrieval or refusal behavior, record: ID; owner and hypothesis; user risk; exact baseline commit and source versions; case-set commit and golden-label reviewer; one planned variable; baseline results for Stage 1, Stage 2A, Stage 2B, adversarial and unit suites where applicable; the expected gain and protected guardrails. After the change, record head commit, the same full-suite outputs, per-assertion diff, new failures, environment, timestamp, latency/tokens and Tirath's keep, revise or revert decision. A new source version or changed golden label gets a separate note, not a silent comparison.

Stop at [RELEASE-GATE.md](RELEASE-GATE.md) if a missed refusal, wrong citation, fictional amount, failing test, stored refusable text or unreviewed content appears. A higher aggregate pass count never overrides that stop rule. The PM value of this registry is not a longer test list: it makes the trade, regression and release call inspectable.
